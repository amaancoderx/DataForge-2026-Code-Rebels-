The Interference Budget

Every fixed-size memory, linear attention, a fast-weight layer, a synapse matrix in Dragon Hatchling, buys constant cost by letting its memories overlap. This page lets you spend that budget until it breaks, then hand you the two repairs the field actually uses.

Concept: Synaptic plasticity as short-term memory Audience: comfortable with matrices + softmax attention ~10 min · 60-second core test Live toy model, no server
The one sentence this page teaches, and lets you falsify

A fixed-size synaptic state stores associations by summing outer products, so it absorbs an unbounded stream without allocating a slot per token, but every memory then shares one matrix, and retrieval is corrupted by a crosstalk term set by the overlap between keys. Two consequences you can force this page to admit or refute: accuracy depends on the ratio N/d rather than on N; and sparsifying the keys rescues accuracy only if the code is also non-negative, which is precisely the pairing BDH's positive activations commit to.

Below is a real associative memory running in your browser right now. It is not an animation. Every number on this page is computed from the matrix you are about to break.

Honesty, up front

The model in this page is a toy associative memory we wrote for teaching. It is not BDH, not a BDH checkpoint, and not a reimplementation of one. It isolates the single mechanism BDH shares with the linear-attention family so you can watch that mechanism behave. Every claim about BDH itself is labelled, sourced to the paper, and marked as reported-by-authors rather than reproduced by us.

Act I · The substrate

One matrix, many memories

We store key → symbol pairs. Each key k is a vector over d "neurons". Each value v is a one-hot vector over 8 symbols, so we always know the ground truth. Writing is one line, and it is the whole idea:

S ← λ·S + v kT // Hebbian write: co-active units strengthen a connection ŷ = S kq / (kq·kq) // read: one matrix-vector product

There is no list of past tokens anywhere. S is 8 × d floats forever. Push the pairs stored slider and watch what that costs you.

What you should have just seen

Perfect recall for a while, then a slide, not a cliff. Nothing ran out of space: the matrix never grew and never shrank, and the state size readout never moved. What degraded was separability. Now do the control experiment: double N and double d. Accuracy should return to roughly where it was.

Across seeds 1-8 our evidence run gets 100%, 98%, 89%, 70% at N/d = 0.25, 0.5, 1.0, 2.0, and it gets those same four numbers at d=64, 128 and 256. The ratio is the variable; the size is not. Reproduce it with node verify.mjs (experiment E1).

Act II · The mechanism

Why it fails: read the crosstalk term

Take the Hebbian state with λ=1 and query it with a stored key ki. Substitute the sum and pull out the term you wanted:

S ki = ( Σj vj kjT ) ki = vi (ki·ki) + Σj≠i vj (kj·ki) ╱__________╱ ╱______________________╱ the answer the interference

Every other memory votes on every query, weighted by how much its key overlaps yours. This is the entire failure mode, and it tells you exactly what to optimise: not the size of the state, but the inner products kj·ki.

With random dense unit keys in d dimensions, each overlap is roughly ±1/√d, and N−1 of them add up like a random walk, so the interference grows like √(N/d). Accuracy therefore degrades gracefully with the ratio N/d, which is exactly the curve you just drew. Push d up and the cliff moves right; push N up and it moves left.

Test the mechanism, not the story

If the explanation above is right, then reducing key overlap without changing d or N must restore accuracy. That is a falsifiable prediction, and it is what the next control does.

Act III · The BDH module

Repair #1, sparsity, and why Dragon Hatchling is built this way

Here is the experiment, and it has a twist that catches most people. Set N=96, d=128 and leave them alone for the rest of this section, capacity is now fixed and cannot explain anything that follows.

First, sparsify the signed code. Drag Active per key from 100% down to 3%. Watch the accuracy readout. It barely moves: our evidence run gets 94.5% → 94.4%. Two random signed sparse keys with a·d active units share about a²d coordinates, but the signs of those shared terms cancel, so the overlap stays pinned near 1/√d ≈ 0.07 the whole way down. Sparsity on its own buys you nothing.

Now switch Key code to ReLU non-negative and start again at 100% active. Accuracy collapses to about 20%, barely above the 12.5% you get by guessing. Of course it does: with no negative entries there is no cancellation at all, every key overlaps every other key by 0.93, and the state is one undifferentiated smear. A dense positive code is the worst associative memory on this page.

Then sparsify that. 100% → 50% → 25% → 12% → 6% → 3%; our run measures accuracy 20.3%, 26.6%, 50.4%, 72.0%, 86.5%, 90.8% with overlap falling 0.93, 0.46, 0.23, 0.11, 0.059, 0.032. For a non-negative code, overlap falls roughly linearly in the active fraction, because there are simply fewer shared coordinates and nothing cancels the ones that remain.

The result worth remembering

Sparsity and non-negativity are not two independent nice-to-haves. Sparsity is what makes a non-negative code viable, and non-negativity is what makes sparsity pay. Either alone is a dead end; together they take the same matrix from 20% to 91% with N, d, and the state size all untouched.

Where this shows up in Dragon Hatchling

BDH is presented as a local graph-dynamics model of interacting neurons in which what a Transformer calls attention is carried instead by synaptic state written Hebbian-style as the model reads. Its state is a matrix σ the authors interpret directly as synapse weights between neuron pairs, and in the normalisation-free form of the architecture the update is literally the accumulation you have been breaking:

σt,l := ( σt−1,l + yt,l−1 xt,lT ) U // BDH-Normfree, Eq. (7) σt−1,l = Στ<t yτ,l−1 xτ,lT Ut−τ // closed form, Eq. (16)

That closed form is the point of contact. BDH's memory is a decayed sum of outer products, purely additive, with no error-correcting term (U is a diagonal or block-diagonal damping/rotation, i.e. our λ and nothing more). BDH therefore sits squarely on the Hebbian side of Act IV's fork, and it must control interference some other way. It does: the paper's own summary of BDH-GPU is "a specific kind of ReLU-lowrank feed-forward network, and a linear attention mechanism, which both operate in the same neuron dimension n, using positive activation vectors." Positive activations, the code you just watched fail at 100% density, paired with reported sparsity of about 5%.

So the sparsity slider is not decoration. For an architecture that has committed to non-negative addressing and additive writes, sparsity is not a tuning knob, it is the thing holding the memory together. And it pays a second dividend: a synapse driven by a handful of neurons can only ever mean a handful of things, which is the structural precondition for the monosemantic synapses the paper reports. Interference control and interpretability fall out of one decision.

Evidence level, read this carefully. Everything in this box about BDH is reported by its authors in arXiv:2509.26507 and has not been reproduced by us. Specifically: the ~5% figure is measured at 4.0-7.5% of y entries non-zero during memorisation (~2.5% during repetition) on a synthetic letter task, not on natural language; the monosemanticity result is two hand-picked synapses on a Europarl-trained model, supported by a Mann-Whitney U test, not a systematic dictionary; the connectivity result is a heavy-tailed degree histogram from one head of one layer, and no power-law exponent is fitted anywhere in the paper, say "heavy-tailed", not "scale-free with exponent α". What is live and reproducible on this page is the general mechanism only: that in an additive outer-product memory, sparse non-negative addressing suppresses crosstalk while dense non-negative addressing destroys it.

Where the analogy stops, four things not to overclaim

(1) BDH's σ lives on synapses inside a full architecture with feed-forward blocks, ReLU gating and normalisation; our S is one bare matrix with none of that. (2) BDH's keys are learned activations and training can actively decorrelate them; ours are random, so our curves are a pessimistic lower bound. (3) BDH is not a state-space model in the Mamba sense, do not file it there; BDH-GPU's own framing is ReLU-lowrank plus linear attention. (4) The paper's language results are character-level Europarl loss curves against a TransformerXL-style baseline, and the headline parity claim is for the gated BDH-GPU′ variant, not a benchmark sweep against GPT-2.

And BDH-CQ? Say what is true, not what is convenient

BDH-CQ (arXiv:2608.09888) is the later sibling: in-context learning with recurrent latent reasoning, where inputs at inference time update a recurrent memory and the answer is computed by iterating in latent space rather than by emitting a chain of thought, with, in the authors' words, no parameters updated at inference. It reports 24.25% pass@1 and 29.5% pass@2 on the 400-task ARC-AGI-1 public evaluation split at roughly $0.0007 per task, from a 150M-parameter model. Those figures are developer-reported, not an independent leaderboard verification, and an AWS blog post quotes 29.2% for the same result, so cite the paper. Its direct relevance to this explainer is limited and we will not manufacture more. The paper describes its state as recurrent memory and relates it to fast-weight and linear-attention views of contextual association; it does not use BDH's synapse vocabulary, and the concept on this page, crosstalk in additive outer-product memory, is grounded in BDH, not BDH-CQ.

Act IV · The other repair

Repair #2, stop adding, start correcting

Sparsity attacks the overlap factor. The delta rule attacks the accumulation instead: before writing, subtract what the state already believes.

Hebbian: S ← S + v kT // pile it on Delta: S ← S + β·(v − S k) kT/(k·k) // write the error, not the value

When a key repeats, Hebbian writing stacks both answers into the same rows and the read returns their sum, so the query lands on a tie broken by whatever crosstalk noise happens to be around. That is why the Hebbian column below sits near 50% and stays there: it is not degrading, it is flipping a coin between the stale value and the correction. The delta rule subtracts the stale value as part of the write, so there is nothing left to tie with. This is the move that separates DeltaNet-style linear attention from the plain additive kind, its authors motivate it exactly this way, noting that a purely additive rule "makes it difficult to deallocate past key-value associations, eventually leading to key collisions."

This is also where BDH sits on the map, and it is worth being precise about it: BDH's published update (Eq. 7/16) is purely additive with damping, there is no delta correction in it. BDH is on the left-hand column below. It buys its interference control with sparse non-negative addressing instead, which is a different design decision, not a weaker version of the same one.

Act V · The trade

What you bought, and what you paid

Softmax attention keeps every key and value and compares your query against all of them. It has no interference term, that is its genuine advantage, and it is why it does not degrade as context grows. It pays for that with a KV cache that grows linearly with the sequence and a read that scans it.

So the honest statement of the trade is not "linear attention is cheaper." It is: linear attention converts a growing memory into a fixed one by allowing memories to overlap, and the entire engineering programme of this family is about managing that overlap, by gating and decay (RWKV, RetNet, GLA), by error-correcting writes (DeltaNet), by test-time memory objectives (Titans), or, in BDH's case, by making the addressing sparse, non-negative and biologically motivated in the first place.

Act VI · Explain it back

Three questions. Answer before you scroll.

Stated limits of this artifact

• Values are one-hot over 8 symbols so ground truth is exact; real models store distributed values, where degradation is smoother and harder to see. • Keys are random (or random-sparse), not learned; learned keys can be far better separated, so our curves are a lower bound on what a trained model achieves. • No softmax, no normalisation layer, no multi-layer stack, no training, this isolates one mechanism deliberately. • The dense capacity heuristic N ≈ d is a rough scale, not a theorem for this setup. • Sweeps are capped at N=160 and d=256 to keep every control under ~50 ms. • All randomness is seeded, so your numbers are reproducible; change the seed in the sandbox to check that no single draw is doing the work.

Act VII · Sandbox

Now break it deliberately

Everything is unlocked. Some experiments worth running, each of which can falsify something said above:

  • Hold N/d constant (N=32,d=64 then N=64,d=128). If the mechanism story is right, accuracy should be roughly the same. Is it?
  • Sparsity at fixed capacity. Set d=64, N=120, dense → broken. Now drop to 5% active. If accuracy recovers without touching d or N, overlap, not capacity, was the binding constraint.
  • Find where sparsity stops helping. Below some fraction, keys have so few active units that distinct facts start landing on identical supports. Locate that floor.
  • Decay as a competitor. Can λ<1 alone rescue the dense case? What does it cost the oldest memories? (Inspect pair #1 versus pair #N.)
  • Delta rule with heavy overlap. Does correcting the write also help when keys merely resemble each other, or only when they exactly repeat?
